# RivicQ contact directory — @rivicq.com

One professional domain for the full RivicQ ecosystem. Every function stays on **rivicq.com** and is centralised in Zoho so RivicQ GmbH owns the records, access, and continuity — not individual mailboxes on personal accounts.

This file is the public directory. **`admin@rivicq.com` is not published.** It is reserved for domain and system ownership, with MFA and recovery details controlled by RivicQ.

Companion: [LEGAL.md](../LEGAL.md) · [PRIVACY.md](../PRIVACY.md) · [SECURITY.md](../SECURITY.md)

## Why this structure

- A single history of leads, grants, MoUs, customers, and contracts.
- Shared ownership: communication continues if a team member leaves.
- Role-based access, MFA, and controlled forwarding.
- Clear separation between research, product, commercial work, and the Innovation Hub.
- A credible enterprise structure for banks, investors, government partners, and regulated customers.

Partner names (cloud, quantum, research institutes) are optional relationships. An address does not imply a signed alliance or a certification.

## Recommended setup now

1. Create the twelve priority addresses first.
2. Make most generic addresses shared inboxes or aliases — not separate paid mailboxes.
3. Give access by role (table above).
4. Use Zoho TeamInbox or shared mailbox rules so every message has an owner, status, and follow-up date.
5. Add **SPF, DKIM, and DMARC** for rivicq.com before high-volume outreach, investor email, or product notifications.

This repository documents the directory. It does not provision Zoho mailboxes or DNS records.

## Product vs mailbox

Login accounts such as `admin@rivicq.com` inside a **self-hosted** Community/Enterprise API are bootstrap identities for that deployment. They are not a public mailbox and must not appear on marketing pages.
