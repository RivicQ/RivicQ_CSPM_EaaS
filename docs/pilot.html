Pilot entry checklist

Do not start a scan until every applicable line is true.

People and authority

  • Named pilot owner, technical contact, and security contact.
  • Written authorization for every target and copied artifact.
  • Data-retention and deletion schedule agreed.

Build and deploy

  • bash scripts/build-pages.sh completes.
  • bash scripts/verify-pages-build.sh passes.
  • API has DATABASE_URL, JWT_SECRET, and CORS_ORIGINS.
  • Console build points at the pilot API or explicitly stays in demo mode.

Evidence

  • Day-one smoke test recorded with build SHA and operator.
  • Acceptance tests recorded individually.
  • Known limitations accepted in writing.
  • Rollback path and incident contact confirmed.

Day-one commands

Run the expected-failure checks deliberately; do not let them abort the shell.

make build-rivicq

set +e
./bin/rivicq scan fixtures/crypto-test --include-fixtures --fail-on BLOCK --format json
test "$?" -eq 1

./bin/rivicq scan . --fail-on BOGUS
test "$?" -eq 2
set -e

bash scripts/build-pages.sh
bash scripts/verify-pages-build.sh
