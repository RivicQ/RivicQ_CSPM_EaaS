Discovery to migration

The engine classifies cryptographic posture. It does not rotate production keys. Community stops at JSON evidence. Enterprise adds continuous monitoring and contracted packs.

01 · Discover

Inventory the estate

Scan a public GitHub repo, website, or host with rivicq scan or the labeled console field. Algorithms, certificates, and declared secret names — never secret values.

02 · Assess

Build the bills of materials

CBOM / SBOM Cryptographic Security Posture Management. Qiskit scores are a local taxonomy — not IBM Quantum hardware. QBOM as a product layer is Enterprise. RSA-2048 is classified; it is not treated as automatically broken.

03 · Remediate

Gate, then patch

The GitHub Action can fail CI on BLOCK findings. Operators apply patches. The product does not silently rewrite keys or destroy cloud resources.

04 · Migrate

Plan classical → PQC

Harvest-now-decrypt-later exposure is scored. Hybrid ML-KEM / ML-DSA is the recommended cut-over. Migration is an operator decision, not an automatic rotation.

05 · Report

Evidence, then packs

Community exports JSON. Enterprise adds DORA-oriented evidence packs and audit history under a commercial contract. Mappings are not certifications.

Workflowrivicq-cspm-operator-workflow.html How does an operator scan run? Discover → Gate → CBOM Console or CLI posts a scan, the engine fingerprints and classifies, the policy gate decides, QBOM stays Enterprise (403 on OSS), and the CBOM report publishes. Workflowrivicq-analysis-workflow.html What happens to each artifact? Fingerprint → Gate → Evidence Every artifact is fingerprinted, classified deterministically, gated as BLOCK / WARN / PASS, and published with a signed evidence pack. Workflowrivicq-compliance-workflow.html How does evidence get trusted? Map standards, attest, or waive Collect, normalize once, map to DORA / BSI / eIDAS / NIST / ISO, then attest or issue a time-boxed waiver — evidence retained and signed. Inventory → Hybrid → Attest Classify every algorithm, plan ML-KEM / ML-DSA hybrids, roll out in phases, and verify before / after with a fresh scan. Sequencerivicq-scanning-sequence.html Who says what during a scan? Auth first, evidence always Console → API → Authn/RBAC → Scanner → BOM store → evidence, with every return and audit event in order.
